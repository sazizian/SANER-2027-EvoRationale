## Diagnosis and measurement boundaries

The supplied v4.3 run had baseline TP=1, FP=0, FN=13, F1=0.133333, and all-scope
TP=1, FP=1, FN=18, F1=0.095238. All 30 labeled sources had been read, but 17 of the
18 missed correct triples were never proposed. A related supersession needed
same-event context; the accepted false positive retained an old QoS invariant
without a substantive supporting change.

The new profile removes that source/target-selection bottleneck and exposes its
remaining coverage gaps. It also explicitly permits material-subclaim support,
while preserving full-element sufficiency for resolved central needs. These
semantic policy changes require locked definitions before a new study.

Two inspected all-only I2/supersedes labels concern interim policies absent from
the fixed original S0 I2. No unseen interim claim is manufactured, and no frozen
reference row is edited. Reference-policy review is separate from code fixes.

**There is no v4.4 hosted accuracy result yet.** Synthetic tests and model-reported
review rows do not prove semantic correctness, improved F1, or generalization.
Known development examples informed this version. Human adjudication and fresh
independent histories are required for effectiveness claims. Existing live
service integrations were not revalidated against external production servers.
