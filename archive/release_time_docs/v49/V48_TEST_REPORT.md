# EvoRationale v4.8 validation report

This is a minimal development repair experiment based on v4.6, the strongest
measured pilot. It restores that version's semantic instructions and response
schema verbatim for event-evidence-repair. Hosted v4.8 accuracy and native
Windows execution have not been measured during construction.

## Executed validation

- **712 tests passed in 201.86 seconds** through the actual
  start_v48_no_api.py helper on Linux/Python 3.12. All 671 inherited regressions
  remain, plus 41 generic repair, pipeline, audit and provenance/workflow tests.
- The actual helper prepared a fresh synthetic evaluation, preserved existing
  Dev01 and selected unused Dev02, then completed the no-provider dry-run. The
  complete v4.7 comparator was pinned alongside the v4.6 model/budget source and
  older comparisons. Previous bytes were unchanged, READY paths were checked
  and the synthetic READY pointer removed. No hosted attempt, run, checkpoint,
  receipt or score was created. Synthetic historical receipts/scores exercise
  provenance transport, not experimental accuracy.
- The extracted ZIP actual start helper passed all 712 tests, preparation and dry-run.
- Python compilation passed. v4.6/v4.7 core trees remain unchanged. The v4.6
  semantic-policy source, relation contract and exact-triple scorer are byte
  identical. Runtime does not contain case identifiers or a reference answer
  table. The new judge inherits the old prompt/schema; it adds no semantic fields.
- Same-artifact added-current context can supply adopted explicit replacement
  proof. Missing old proof, unknown/proposed authority, scope mismatch, missing
  material change, unestablished contract, removed/unchanged-only context and
  unrelated foreign proof cannot use this path. Historical rejection behavior
  is preserved. Existing qualified current support, same-event adopted
  dependent migrations, partial central needs and model-assessment metadata
  remain. The larger initial allowance respects the existing 16,384 ceiling.
- A repeated completed run verifies receipt, input/source, report/manifest and
  checkpoint, then returns its existing path without credentials, mutation or
  provider calls. Changed checkpoint or incomplete output rejects and remains
  preserved. Complete scores are committed, verified and reused without changing
  bytes or modification times. Parent/reference and score receipt hashes are
  checked; tampered scores cannot be silently reused. Diagnostic bundling checks
  the score commit receipt and completed checkpoint.

## Actual-source structural preflight

The supplied approved S0 and the identical 53 unlabeled sources were audited
without Gold or provider access. Six batches [14,6,5,1,2,2] cover all 30 diff
versions. Exact positions/roles for 68 passage handles and 677 line handles
passed. Of 412 changed lines, 410 are safely quotable; two screened gaps remain
explicit. Input bytes and human approval were unchanged. Unread metadata and
absent rationale remain coverage limitations.

Six negative local transport envelopes require **53,495
estimated input tokens** within the nominal 100,000 in the no-retry scenario.
Initial output allowances [16,200,8,200,7,200,6,144,6,144,6,144] stay below the
16,384 request ceiling. The classifier uses one phase with no nomination;
positive outputs may still need bounded retry. These envelope estimates are
not provider tokenization, billing, latency or semantic-performance evidence.

## Every stored v4.6 interpretation replayed

All 23 old effects were rebuilt from their existing exact-source assessments,
without changing claims, quotations or selected source proof. The old policy
again accepts 19 and rejects 4. The repaired policy accepts those same 19 plus
the single same-artifact replacement formerly rejected for proof location;
the other 3 remain rejected. Twelve local fixture responses and zero provider
calls were used, with no Gold read. The original response schema is unchanged.

This deliberately includes previous false positives. It checks source-guard
compatibility and the routing repair. It does not show that a fresh model call
will reproduce the stored judgments and is not a new prediction, precision,
recall or F1 result.

## Measured regression and remaining limits

Actual v4.6 baseline/all F1 is 0.689655/0.631579. Actual v4.7 is
0.181818/0.333333. v4.7 lost all ten baseline true positives and retained only
two of twelve all-scope positives. No missed positive was rejected downstream:
the model omitted or reclassified them. All twenty v4.7 score errors and their
actual old/new assessments are included in V47_DIAGNOSTIC_REVIEW.md and
development_review/v47_runtime_analysis.json. v4.6 remains the measured reference.

**Hosted v4.8 accuracy is unknown.** Instructions/schema are restored, but the
proof gate, initial output allowance and request format name differ. Models are
opaque IDs, not verified immutable snapshots. Self-reported authority,
entailment and completeness remain MODEL_ASSESSED, not semantic proof or deployed
validation. Passing software tests cannot establish interpretation accuracy.
Known development examples informed changes; this is not held-out or optimal
architecture evidence. S0, Gold, denominators and previous results are unchanged.
Interim target mismatch, observability granularity, reporting dependency scope,
freshness and alternative-cost applicability remain disclosed. Human review and
REVALIDATE/UNRESOLVED can remain appropriate.
